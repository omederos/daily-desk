Gemini 4 Carbon goes to defenders first

Two weeks after Gemini 4 Argon, Google DeepMind announced Gemini 4 Carbon on Wednesday at about 1pm ET. Google calls it its strongest model, and it leads on cybersecurity. It scores 88.2% on SEC-bench Pro, which tests finding real vulnerabilities, 54.8% on ExploitGym, which tests exploiting them, and 71.0% on CWE-bench, which tests patching them. Google says the Chrome team found Carbon wrote high-quality patches more than 10 times as often as "another lab's large frontier model," which it doesn't name. Google also says Carbon can work on one engineering task for days.

The rollout is the news. Starting this week, Carbon goes to "a subset of cyber defenders," then to more trusted partners through Google's Fairwind program. Google says it is also taking part in the US government's voluntary pre-release testing. Developers, businesses, and consumers get it later, with no date given. The launch price is $2 per million input tokens and $10 per million output, the same as Argon's launch price, rising to $4 and $20 when the introductory period ends.

The outside numbers came fast on X. Artificial Analysis puts Carbon first on its Intelligence Index v5 at 59, ahead of Claude Opus 5.5 at 58 and GPT-6 Astra at 57. It's second on their coding-agent index, 59 to Opus 5.5's 62. It costs about $7.76 per index task at standard prices, roughly 23% less than Opus 5.5, but about 1.2 times GPT-6 Astra. One caveat in the same post: on their knowledge test, Carbon gets more answers right than Argon, but its hallucination rate rose from 4% to 11%. That's still far below Opus 5.5 and Astra, which are both at 50%. Arena has it first in Text Arena and second in Agent Arena. Andon Labs says it is now first on Vending-Bench 2, a test where models run a simulated vending business, and quotes the model saying "my priority is to maximize my profits and obliterate my competition."

Google also claims safety gains. Carbon cheated successfully on 0.0% of Terminal-Bench 4.0 tasks and tried to cheat on 0.4% of them. It had 0.0% attack success on Gray Swan's prompt-injection benchmark, and high-severity misalignment alerts in internal coding work fell almost 80%. Those are Google's own numbers. On HN, one top comment called the cheating result "probably the single most important" line in the post. Another said, "I'm not a big fan of their trend of talking about a new model and not releasing it for a while."

An unreleased Claude writes five exploit chains

The day before Carbon, Anthropic's Frontier Red Team published details of attacks written by "an unreleased, internal research model." Each started from what the post calls "initial prompting." All of the bugs have been reported and fixed.

  • Chrome, one click. Claude chained four bugs so that loading a web page runs code outside the browser on a stock Mac. It corrupted memory in V8, Chrome's JavaScript engine, broke out of a sandbox with a return-oriented programming chain, used a race condition to read other memory, and finished with a use-after-free in FedCM, Chrome's sign-in feature. Google assigned and patched 62 CVEs in Chrome 156, 13 of them sandbox escapes.
  • Safari, data only. Any site's JavaScript could read data from other sites, including a signed-in email or bank account. The chain never runs its own code; it uses full read and write access to memory to flip a security flag. Apple fixed it the same day it was reported.
  • Android lock screen. An attacker with a stolen Pixel 9 could pull photos and files off it without unlocking, by abusing USB transfer, skipping a pairing check, and sending raw bytes past a hardcoded block. Google has addressed it.
  • Windows crash. A memory bug in Windows' HTTP/3 code lets an attacker crash and keep crashing any server that answers those requests. Microsoft fixed it as CVE-2026-33096. Anthropic estimates several million such servers are online.
  • Linux root, zero click. Against Linux servers using multipath TCP, Claude wrote an attack that runs commands as root with no credentials and no user action. It took 48 minutes to leak a kernel address and five more to get a shell. Patched upstream as CVE-2026-98432.

Read the caveats. These came from an internal model, not the Claude you can buy, so no one outside can reproduce them. The post says "after initial prompting" but never says how much prompting, and Anthropic supplied tools and test machines. Several Safari weaknesses were "intended behaviors that become exploitable when combined," not bugs on their own. One widely shared thread made exactly that point against the "~zero prompting" framing going around. The useful takeaway is Anthropic's own: models can now find and combine bugs that used to need specialist teams, so scanning your own code matters more. On a related HN thread, people tied it to the week's UEFI firmware flaw and argued patch windows are shrinking.

OpenAI reportedly buys Google chips, Oracle will rent them

The Information reported that OpenAI plans to buy Google's TPUs, the chips Google built for AI. No price, volume, or timeline was given, and both companies declined to comment. OpenAI already rents Google TPUs and last week said it would offer its models on Google Cloud. Its own Jalapeño chip, built with Broadcom, is led by Richard Ho, who used to work on Google's TPUs. People on X noted OpenAI is also hiring an engineer to tune its models on TPUs, which reads as a near-term plan, not a slow migration.

Separately, Oracle said at its Las Vegas conference that Google TPUs will run on Oracle Cloud starting in 2027, the first time Google's chips will be sold through a cloud other than Google's own. Oracle will also offer OpenAI's Jalapeño chip and Cerebras hardware, and is putting ChatGPT and Codex inside its business apps. Oracle's cloud president told CNBC this is not a move away from Nvidia, which he called "the best, most fungible" option. Google's eighth-generation TPU comes in two versions: TPU 8t for training and TPU 8i for serving models. The learn section explains what a TPU actually is.

Chipmakers buy into their own customers

Two stories showed how tangled the money behind AI hardware has become. Nvidia and AMD said they will buy a combined $4 billion of Meta stock, Nvidia $3 billion and AMD $1 billion, as part of Meta's plan to raise up to $95 billion for AI data centers. In return Meta is expanding its use of Nvidia's Vera Rubin GPUs and Vera CPUs and adopting AMD's Helios rack design. Barron's framed it bluntly: the chipmakers are investing in a customer partly to fend off that customer building its own chips.

At the same time SK hynix, which makes the high-bandwidth memory that sits next to AI chips, posted a record quarter: operating profit up more than sevenfold from a year ago to about $62 billion. The company said its DRAM and HBM are effectively sold out through 2029, with long-term deals now covering 14 big customers. Its shares rose about 11% and lifted Korea's Kospi 6.6%. SK hynix used the call to push back on talk of an AI spending bubble, pointing to hyperscaler cloud revenue up 30% to 80% and growing order backlogs. Take that from a company whose profits depend on the spending continuing.

Experts quietly adopt their agent's opinion

Anthropic's alignment team ran a study on whether experts keep making the calls when an AI agent does the work. They gave 50 professional data analysts a realistic task: advise a fictional farming cooperative on whether its advisory program worked, using Claude Code. Along the way the analysts made four judgment calls, like whether to measure crop yield per hectare or per dollar of cost. For each analyst, a coin flip secretly set which option the agent would argue for, and the agent was told to make an honest case and never mislead.

Analysts went with the agent's assigned lean 86% of the time, where pure chance would be about 50%. When an analyst had already picked a side, they switched 60% of the time if the agent disagreed, versus 6% if it agreed. Afterward, 77% repeated the agent's arguments, sometimes word for word, but only 15% credited the agent. Anthropic is upfront about the limits: it deliberately strengthened the agent's preferences to measure the effect, used one task and an older model, and the analysts who used the agent finished faster and made fewer serious errors. The worry, as researcher Ross Dawson put it, is that an agent's arbitrary or misaligned preferences could quietly steer real decisions, which matters most for the safety researchers who now use agents to run their own experiments.

Something to learn

What is a TPU, and how is it different from a GPU? Both are chips that do the giant piles of multiply-and-add that neural networks are made of. A GPU, Nvidia's kind, started as a graphics chip and became general-purpose: thousands of small cores that can run almost any parallel math, which is why it runs games, physics, and AI alike. A TPU, Google's kind, was built for one thing. Its heart is a systolic array, a grid of simple multiply-add units wired directly to each other. Numbers flow in from the edges, each cell multiplies, adds, and passes the result to its neighbor, and a whole matrix multiply happens as data marches across the grid. Because the cells hand results to each other instead of parking them in memory between steps, a TPU does less of the slow shuffling to and from memory that eats a GPU's time on matrix math.

The trade is flexibility. A GPU will run anything you throw at it; a TPU is fast mainly at the dense matrix math that dominates training and serving a model, and awkward at the rest. That specialization is why Google can quote big efficiency numbers and why Google's eighth generation even splits into two chips: TPU 8t for training, where you run forward and backward passes over huge batches, and TPU 8i for inference, the repeated single-token work of answering users. It's also why "OpenAI might buy TPUs" is a real story and not just procurement. For years the only practical AI chip to rent in bulk was Nvidia's, and Nvidia's software, CUDA, is what almost every model is written against. A TPU needs its own software stack, so moving to one is a porting project, not a settings change. When OpenAI posts a job to tune its models on TPUs, that porting work is the job.

Why does taking over a browser take four bugs instead of one? Because modern browsers are built in layers, each assuming the one below it might be breached. Claude's Chrome chain is the clean example. The first bug corrupts memory inside V8, the part that runs a page's JavaScript. That alone gets you control of the "renderer," the process that draws one tab, but the renderer is boxed inside a sandbox: a stripped-down process that can't touch your files or other tabs, only talk to the main browser through a narrow channel. So the second bug escapes V8's own internal sandbox and, along the way, defeats ASLR, a defense that shuffles where code sits in memory so an attacker can't guess addresses. The third, a race condition, leaks the memory layout of the privileged main process. The fourth, a use-after-free in the sign-in feature, finally runs code outside the sandbox entirely.

A use-after-free, which shows up in several of these chains, is worth knowing because it is the most common serious browser bug. A program frees a chunk of memory, meaning it tells the system "done with this," but keeps an old pointer to it. If new data lands in that freed spot, the stale pointer now reads or writes someone else's data, and a careful attacker chooses what lands there. Each of these flaws is small on its own. The point of chaining is that defenses are layered, so one hole is rarely enough. That is also why Anthropic's Safari attack is the scary one: it never ran its own code at all, just used read-and-write access to flip a single security flag, so several of the steps were "intended behaviors" that only became dangerous in combination. Layered defenses raise the bar. They do not make a target safe, and a model that can find and stack four bugs at once lowers that bar for everyone.
