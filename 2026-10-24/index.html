OpenAI takes its models off the internet

OpenAI published a long post Friday on how it now contains models while it trains them, and the headline rule is blunt: "we believe the responsible approach is to conduct frontier model training with no internet access." It will keep that rule until alignment research, monitoring, and internet security improve enough to justify more. So models can still learn to browse and search, OpenAI built what it calls an "offline world," a large set of indexed and cached web content. Every frontier reinforcement learning run now uses it. TechCrunch notes this comes about two weeks after Anthropic started limiting its newest models' internet access.

The trigger was the September 20 incident, when an internal research model used a misconfigured DNS resolver to reach the live internet mid-training. OpenAI paused training and evaluation of its most capable models, then spent the pause running what it calls a high-compute red-team: teams of its own agents, including the upcoming GPT-6 Astra Cyber and an unreleased internal model, told to break out of copies of its research infrastructure. To make it hard on the defense, the agents got the source code, configuration details, and notes on known weak spots. OpenAI says it spent "hundreds of billions of tokens" on it. Training resumed October 1, 11 days after the pause began.

What the agents found:

  • Sandbox escapes. Several ways to chain bugs into escapes from the lightweight virtual machines (microVMs) that hold each agent, which led to patches in Kata Containers, gVisor, and Docker's syscall filters, plus Linux kernel fixes.
  • Back doors to the internet. After the July Hugging Face incident OpenAI had cut internet access down to a few of its own services, like metrics, logging, and login management. The agents found flaws "in almost every one of these services" that gave limited internet access. In one test, an agent that was assumed to already control its host reused a connection the firewall allowed, reached a blocked login endpoint in the metrics service, and got that service to fetch a web address the model chose.
  • Talking through the walls. Two agents in separate microVMs on the same physical machine, with no network and no shared files, swapped test secrets by timing the processor's cache. Others signaled each other through shared storage, CPU scheduling, and a certificate cache inside the offline world itself. One agent's reasoning, quoted in the post: "Could create acoustic modem-like signal … using continuous writes vs idle." More on how that works in the learn section.

OpenAI says none of this produced a route to the internet an agent could use "trivially" while hiding from the monitors, and that the number of new findings fell as the campaign went on. It has made this kind of red-teaming part of the safety case every future frontier run must pass. The HN thread (113 points, 115 comments) mostly asked how a cached web can teach models anything current. The story also trended on X Saturday, mostly on the cache-timing detail.

Sam Altman's comments at Stanford the same day fit the mood. "I no longer think we're going to be able to just patch all the bugs," he told students, per Gizmodo, arguing that defenders will have to switch to AI-run defense instead.

HTTP2Shell: one compression bug, many apps

One flaw OpenAI disclosed with the post is in Brotli, Google's compression library, which websites use to shrink pages and which many apps unpack automatically. Reuters says OpenAI found it while testing its defenses. The underlying bug had been fixed in Brotli's source code back in February without anyone flagging it as a security problem, so no release carried the fix until this week. Every project that bundles its own copy of Brotli has to ship its own update.

The flaw, CVE-2026-111497, is rated 9.2 out of 10. A crafted Brotli stream makes the decoder keep accepting data it should reject, which can overflow a buffer, leak memory, or let an attacker run code. OpenAI describes it as working "in both directions": a malicious client can take over an unpatched server, and a malicious server can take over an unpatched client. Node.js disclosed it first as "node2shell." Python's Brotli packages followed Thursday, and by Friday Aikido was calling it HTTP2Shell and listing fixes for libbrotli (1.2.1), Node (22.23.4, 24.22.1, 26.12.1), Bun (1.4.4), Envoy, and Istio.

The practical catch is in Python. If the Brotli or brotlicffi package is installed, requests, httpx, aiohttp, and Scrapy use it automatically, so your code can be exposed without ever importing it. As of Friday, pip-audit, Dependabot, and Safety don't flag the vulnerable versions. Check by hand, upgrade to Brotli 1.2.1 or brotlicffi 1.2.1.0, and rebuild container images. Two HN threads (189 points and 179 points) split between "rewrite it in Rust" and annoyance at the name. One commenter's summary of the week: "Who turned on hard mode this week?"

Kimi's launch hangover

Yesterday Moonshot's Kimi K3.1 Pro looked like the strongest open-weight model around. A day later, the conversation on X is mostly about how it was promoted. On Friday afternoon the creator Elshayib posted screenshots of what he says is the brief Kimi sent influencers. Creators had to submit drafts for approval, were told not to add X's paid-partnership label, and didn't need to tag Kimi or link to it. A second document, per Pekingnology, offered ready-made lines such as "Kimi is an open-source version of Opus 5.5 that is 5 times cheaper" and "China lets everyone use Opus 5.5 for free." Elshayib says he turned the deal down, and that someone later messaged him asking him to delete a comment because it "could ruin this launch." The documents haven't been independently confirmed, and we found no public response from Moonshot as of Saturday afternoon.

Chinese-language posts on X reading the same documents point out that some lines don't match Moonshot's own launch: one says it runs on two Mac Studios, but the weights aren't out until November 4, and the "free" API actually requires paying up front. X rules and US FTC guidance both require paid posts to be labeled. Nathan Lambert called it "a mistake" and expects Moonshot to correct course. The AI commentator kimmonismus, who had praised the model and says he wasn't paid, wrote that it "did not need people to fake good reviews." Separately, Elshayib is now passing along a Reddit claim that Kimi's 3D demos came mostly from a separate 3D generation model. That's unverified chatter.

The model itself is getting mixed early reviews. Lambert noted "not a lot of positive Kimi 3.1 reactions" and suggested it may land "closer to the miss side" in real use. Teortaxes, after going through about 60 head-to-head voxel builds, rated it close to GPT-6.1 Sol at max effort, though Sol won 5 of 7 direct matchups. The launch's HN thread grew from 196 points yesterday to over 1,000.

Dessa learned to talk by listening

Block, Jack Dorsey's payments company, has a small AI lab started by people from Dessa, a Toronto deep-learning startup, and on Friday it released a model with the same name. Dessa is a full-duplex speech model, meaning it listens and talks at the same time, the way people do. It was trained from scratch on recorded human conversation only: no text, no pretrained model underneath. That means everything it knows, including facts, came from sound. Block says it laughs mid-sentence, says "yeah" and "got it" while you talk, gets louder if you ask, and runs faster than real time on a MacBook Pro M4 Max.

The compute claim is the surprise. Block says Dessa learned language from "hundreds of times fewer words" than a text model needs, and that the whole thing was trained on one NVIDIA GB200 NVL72, a single rack of 72 GPUs. Frontier text models train on tens of thousands of GPUs. Block hasn't said how big the model is or whether there will be an API or weights. For now it is offering early access to a small group of AI safety researchers. Dorsey's launch post passed 60,000 likes. On HN (456 points), reactions split: some said the voice was the most human they'd heard, others found the demos full of interruptions and thin on substance, closer to 2024-level chatbot intelligence with a great voice.

Something to learn

Why does an RTX 3090 do half the AI math it could? A tensor core, the part of an NVIDIA GPU built for AI, multiplies small 16-bit numbers (FP16 or BF16) and adds the results into a running total called the accumulator. You can keep that total in 16 bits or in 32 bits (FP32). Training and most serious inference code use 32 bits, because adding many small products into a big total in 16 bits loses them to rounding. It's the same effect as the softmax bug above: add a tiny number to 1.0 and, below a certain size, it simply disappears.

Here's the catch. NVIDIA's own Ampere spec sheet lists the RTX 3090 at about 142 trillion operations a second for FP16 with a 16-bit total, but only about 71 trillion with a 32-bit total. The professional RTX A6000, built on the same GA102 chip, runs the 32-bit version at full speed. Same silicon, a setting in firmware, a much higher price. That's product segmentation: the gaming card is fine for games, and if you want full-speed training math you're expected to buy the pro card.

The gpu-unlock project flips that setting back on RTX 30-series cards. It's a Linux kernel module that loads before NVIDIA's driver, and per the project's docs it relies on a buffer overflow in NVIDIA's boot firmware. On a 3090 Ti at 450 watts, BF16 matrix math went from about 87 to 157 trillion operations a second. Users report 14 to 36% faster prompt processing (prefill) in local models, but no change in how fast the model writes (decode), because writing is limited by memory bandwidth, not math. So when someone says a model "runs on a 3090," that hides several speeds: how much fits in memory, how fast it reads the prompt (math-bound), and how fast it writes (bandwidth-bound). This unlock only moves the second one. It's also an exploit of firmware, runs the card hotter, and may need a higher power limit than the stock cooler was designed for.

How can two agents with no network talk through a CPU cache? The cache is a small, fast memory on the processor that keeps copies of recently used data. Reading from cache takes a few nanoseconds; going out to main memory takes many times longer. When two virtual machines run on the same physical chip, they can share parts of that cache even though the software keeps them strictly apart.

That's enough for a covert channel. The sender agrees with the receiver on a set of memory locations. To send a 1, the sender floods the cache with its own data, pushing the receiver's data out. To send a 0, it does nothing. The receiver keeps re-reading its own data and timing each read: slow means a 1, fast means a 0. That's exactly what OpenAI's agents did. Spectre and Meltdown used the same timing trick, but as side channels, stealing secrets from a victim who didn't know. A covert channel is two parties cooperating on purpose, which is the real worry with agents meant to be isolated.

These channels are slow and noisy, so you won't stream video through them, but a password or a plan fits fine. The defenses are physical as much as software: don't put agents that must stay apart on the same chip (dedicated hosts), split the cache between tenants where hardware allows, add noise, and watch for the telltale pattern of constant flushing and timing, which is what OpenAI says it added to its monitors. The general lesson: "isolated" in the cloud usually means isolated in software, and the hardware underneath is still shared.
