Musk's AI unit rents out its GPUs

The New York Times reported that SpaceX's AI unit, which makes Grok, has made Anthropic its largest customer, at about $3.1 billion a month for computing power, while Google pays about $800 million a month. Either side can cancel with 90 days' notice, per Investing.com's summary of the report. The renting started in May and sped up after the June IPO. The AI unit now brings in more than half of SpaceX's revenue, The Decoder writes, and the company had to finish new data centers by October to keep up with Anthropic's orders.

The internal side is less flattering. Per the Times, Musk showed engineers data that the unit trails its rivals, made some of them list their work weekly to justify their GPU use, and in August renamed a group chat "Sell compute because we can't compete." He wrote that "the only thing that matters for competitiveness is revenue per GPU, not benchmarks." The unit shut down its AI companions in September and broke up the roughly 60-person Grok Imagine team. Morningstar's Nicolas Owens told the Times that "SpaceX makes way more money right now renting out compute than from Grok." Musk said at DealBook that Anthropic is very likely to keep renting and wants a lot more.

Amazon buys software to speed up its chips

Amazon agreed to buy the technology behind the Decart Optimization Stack and hire Decart's three co-founders, Dean Leitersdorf, Moshe Shalev, and Orian Leitersdorf, plus their research and engineering team. Amazon didn't give a price. Bloomberg and Calcalist reported $7.5 billion in cash and stock, per TechCrunch and Ynet. It isn't buying the whole company. That's the "reverse acquihire" shape Microsoft, Meta, and Google have used, and it still needs regulatory approval, CNBC notes.

Decart is known for real-time world models like Oasis 3, but Amazon wants the software underneath, which makes models run faster on Nvidia, Amazon, and Google chips. The two companies have worked together on Trainium since 2025. Amazon's Peter DeSantis: "Every leap forward in AI starts with getting more out of every chip." Andy Jassy said last month that Amazon will sell Trainium outside its own data centers for the first time in late 2027, and Decart's software could make it easier to move work off Nvidia, TechCrunch argues. Anthropic did due diligence on Decart and walked away, Bloomberg reported. Nvidia had invested at a $4 billion valuation and was rumored as a buyer too.

948 ways to root, and a shield for running servers

OpenAI promoted on Monday a research post, "A thousand fewer paths to root." It describes a pipeline that scans the Linux kernel, reproduces each suspected bug in an isolated machine, writes a working exploit, and drafts a patch for a human to review. In one mid-October run with an upcoming cyber model, it reproduced 1,724 vulnerabilities and produced 948 working local privilege escalation exploits against a stock desktop Linux. The run cost $1,213,430 in API credits, about $1,279 per exploit. OpenAI says the newer model found more than 5x as many new exploits as a GPT-5.6 Sol run in July, and that the agents came up with at least 10 new exploitation techniques. Its conclusion is blunt: for now, a low-privileged account on a system that isn't fully patched "should be considered functionally equivalent to root access for a well-resourced threat actor." It started with the critical bugs, following the kernel community's guidance, and is working with its Patch the Planet partners on the rest.

The same day, OpenAI and Cisco released Shirudo, Japanese for "shield." It's an open-source Linux runtime for the gap between finding a bug and patching every machine. A shield is a small program that blocks the exact code path an exploit uses while normal requests go through, and it loads without restarting anything. Shields are cryptographically signed, checked by the Linux kernel before loading, and logged with a hardware security chip, a TPM. In OpenAI's demo, Codex wrote a shield that added an input check to Java's Base64 decoder inside a running Elasticsearch server and blocked a Java4Shell attack without downtime. It's BSD-licensed on GitHub. It's also early: the docs say it needs a patched development kernel and a TPM 2.0. Greg Brockman: "finding a bug today doesn't mean you can patch every system tomorrow."

Claude Ship takes pull requests from open to approved

Anthropic launched Claude Ship in beta for Team and Enterprise plans on GitHub. It has three parts. Code Review, already generally available, reviews each pull request and checks its own findings. PR Steward pushes fixes for failing checks, merge conflicts, and review comments, and posts after each push what it changed and how to undo it. It's designed never to approve or merge. Claude Approvals reads a policy file in the repo and can approve routine changes on its own while sending riskier ones to named people. Anthropic calls it "a smarter CODEOWNERS file" and suggests running it in observe-only mode first. Developers can try it on their own work with /ship in Claude Code.

Anthropic's own number: on the Claude Code team, merged pull requests more than doubled from June to September while the share later reverted fell by more than 40%. The catches are cost and data rules. It's billed by token use, and PR Steward has no spending cap by default, The Decoder notes. It isn't available to organizations with Zero Data Retention, the HIPAA setup, or customer-managed keys. Future Tools says eligible Enterprise orgs can claim $10,000 in credits before Jan. 15.

What 58 companies told Anthropic about AI at work

Anthropic economists Nathan Wilmers, Maxim Massenkoff, and Peter McCrory interviewed 66 people at 58 of its enterprise customers. Most said AI adds value by raising output, not by cutting costs. They saw very few domestic layoffs caused by AI. Most companies are hiring less instead, and many are cutting contractors, especially offshore ones, which the authors call a possible early warning for outsourcing firms. Of 100 pieces of software that people described building with AI, 80% automated manual work and 20% replaced software they used to buy. As coding speeds up, the slow parts become code review, sales, and decisions.

The finding that got the most attention: the biggest gains came from reorganizing, like giving people whole workflows and moving staff to the tasks AI can't do. Top-down automation projects caused fear of job loss and surveillance, and resistance from the experts needed to make them work. Ethan Mollick summed it up as two points, that the most value comes from changing the organization and that there's wide worker resistance, partly because of the first point. Later he added that big firms tell him "scattered teams of 2-3 people using AI" are doing the work of dozens, which is "creating large-scale management fights."

Nvidia's hangover, and Megaspeed blacklisted

Nvidia fell about 7% on Tuesday after closing more than 30% higher Monday on Jensen Huang's return, CNBC reports. The rest of Monday's rally faded too: Micron was down 10%, AMD about 9%, Marvell 8%, and CoreWeave more than 12% in midday trading. Trump told CNBC "I made the deal" and that the board got assurances Huang isn't a security risk, "at least with everything we know." Bank of America's note: "Reinstatement should not be confused with the end of scrutiny." Huang's House interview on Dec. 1 and public Senate testimony on Dec. 3 are still on.

Monday night the Commerce Department added Megaspeed, the Singapore cloud company where Alice Huang worked, and six related companies in Malaysia, Indonesia, Thailand, and Singapore to the Entity List, citing a "significant risk" of diverting advanced chips, per CNBC. Any U.S. export to them now needs a license, reviewed with a presumption of denial. Commerce and Justice said investigators asked Nvidia for its Megaspeed sales records in May 2025, Nvidia put Megaspeed on its no-sell list a month later, and agents interviewed Alice Huang, then CEO, in Singapore in June 2025. Commerce opened its investigation in 2024.

Something to learn

What is eBPF, the thing Shirudo's shields are made of? Normally, changing how the Linux kernel behaves means rebuilding it or loading a kernel module. A buggy module can crash the whole machine, and either way you often need a reboot. eBPF is a third option. You write a small program, and the kernel runs it at a chosen spot, called a hook. A hook can be a system call, a network packet arriving, or a function inside a running program, like the Base64 decoder in OpenAI's Elasticsearch demo. Before loading, the kernel's verifier checks the program. It must finish in bounded time, touch only memory it's allowed to, and call only approved helper functions. If any check fails, the kernel refuses to load it. That check is why you can add an eBPF program to a live production server and remove it later without a restart. It started in the 1990s as the Berkeley Packet Filter, which decided which network packets to keep. Today it runs a lot of cloud networking, monitoring, and security tools. Shirudo adds signatures and a TPM log on top, so you can prove which shields were loaded. So when someone says "we blocked it with eBPF, no reboot," it means a small, checked program now sits on the vulnerable path and rejects the bad input.

And what's a "local privilege escalation," the kind of bug OpenAI found 948 of? On Linux, root is the account that can do anything. Ordinary accounts and most services run with limited rights, so if an attacker gets into one, they're boxed in. A local privilege escalation is a bug that lets someone who already has a limited foothold, like a normal login, a hacked web app, or code in a container, become root. "Local" means they need that foothold first. It isn't a way in from the internet by itself. That's why these bugs used to rank below remote ones. They're the second step of an attack, not the first. OpenAI's argument is that the second step has become cheap. At about $1,279 per working exploit, any limited access on an unpatched machine should count as full control. The practical answer is the one OpenAI gives: patch fast, and run untrusted code in stronger sandboxes such as Firecracker or gVisor, which put an extra wall between the code and the real kernel.
