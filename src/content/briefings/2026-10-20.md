<h2 id="deepinfer">DeepSeek opens up the engine behind its API</h2>
<p>At 5:30am ET DeepSeek <a href="https://x.com/deepseek_ai/status/2112476496283775135">posted on X</a> that DeepInfer, "our in-house inference framework," is "now fully open source." The code is on <a href="https://github.com/deepseek-ai/DeepInfer">GitHub</a> under Apache 2.0. It runs one model, DeepSeek-V4.1-Flash, on two kinds of chips: Nvidia's Blackwell data-center GPUs (SM100) and Huawei's Ascend 950. Inside are DeepSeek's own kernels (FlashMLA, DeepGEMM, DeepEP), expert parallelism with a load balancer, speculative decoding that drafts up to five tokens ahead, structured outputs, and modes that make the same prompt give the same answer every time. DeepSeek also released <a href="https://github.com/deepseek-ai/deepseek-recipe">deepseek-recipe</a>, the Rust code that turns Chat Completions, Responses, and Messages API calls into tokens the same way DeepSeek's official API does. The post had 27,700 likes and 2.8 million views by early afternoon. The Hacker News thread hit <a href="https://news.ycombinator.com/item?id=50163277">1,885 points</a>, the top AI thread of the day by far.</p>
<p>The numbers worth reading are in a <a href="https://github.com/deepseek-ai/DeepInfer/blob/main/doc/inference_deployment_qa.md">deployment Q&amp;A</a> that shipped with the code. DeepSeek says a single cluster serves <strong>155 trillion</strong> tokens a day and earns <strong>$38</strong> per GPU-hour "at valley pricing," its off-peak rate. Prompt reading (prefill) runs on ordinary 8-GPU servers. Writing (decode) runs across 64 to 128 GPUs at once, with the model's experts spread over all of them. DeepSeek keeps the cached work on prompts for more than <strong>72 hours</strong>, so a repeated prompt skips the expensive read. Storage is sized at about 14.4 TB per GPU. The Q&amp;A says the smallest efficient setup is 64 GPUs for prefill plus 64 for decode. Its one joke is about splitting those across data centers, which works "at some cost in reliability, e.g., the fiber running between data centers is easily severed by construction work."</p>
<p>The README is upfront about what's missing. It lists three things a real service needs that are "not included in this release": a KV cache system, the split of prefill and decode onto separate machines, and load balancing across replicas. The Q&amp;A explains why: "The KV cache management and load balancing components of the inference system are tightly coupled to our internal infrastructure, so that code is not yet fully open-sourced." So "fully open source" on X and "not yet fully open-sourced" in the docs went out the same morning. What you can run today is offline inference on your own cluster. The parts that turn GPUs into $38 an hour stayed in Hangzhou.</p>
<p>It still matters. The vLLM team, whose engine DeepInfer started from, <a href="https://x.com/vllm_project/status/2112480719952138301">thanked DeepSeek</a> for crediting open source and said it will fold ideas from DeepInfer into its own V4.1 Flash support. Clouds that already serve DeepSeek's models can copy the kernels and the scheduler today. <a href="https://thenextweb.com/news/deepseek-deepinfer-open-source-inference-engine">The Next Web</a> notes the speed figures are DeepSeek's own, and nobody outside has tested them yet. And the timing is pointed. The release came a day after the US ordered civilian federal agencies to remove DeepSeek, and it ships production code for Huawei's chip next to Nvidia's. This story was shaped by X. The Learn section covers two of its features, batch invariance and the expert load balancer.</p>

<h2 id="pytorch">PyTorch gets a native TPU, a day after Trainium</h2>
<p>Yesterday this page covered TorchNeuron, which makes Amazon's Trainium a standard PyTorch device. Today, at PyTorch Conference in San Jose, Google <a href="https://cloud.google.com/blog/topics/ai-infrastructure/torchtpu-is-now-open-source-run-native-pytorch-on-tpus">open-sourced TorchTPU</a>, which does the same for its TPUs. It was built with Meta's PyTorch team. The code is <a href="https://github.com/google-pytorch/torch_tpu">on GitHub</a> and installs with <span class="mono">pip install torch_tpu</span>. Same split as Trainium: debug in eager mode, then use <span class="mono">torch.compile</span> for speed. Hugging Face Transformers v5 now takes <span class="mono">device_map="tpu"</span>, and vLLM, SGLang, Ray, and the TorchTitan training library all have TPU backends. Google says TorchTitan training on TorchTPU reached up to 52% of the chips' peak math on Qwen 3 8B and scaled to 8,192 Ironwood TPUs. Those are Google's numbers.</p>
<p>Meta's quote explains why Google bothered. "We cannot be constrained by a single hardware architecture," said Jana van Greunen, Meta's director of PyTorch engineering, and Meta says it is moving LLM, ads, and recommendation work onto TPUs. Two big Nvidia customers now have a one-line way to try someone else's chip, and the hard part is the same one the October 19 Learn section covered: how many operations actually run fast once you get there.</p>
<p>Google also shipped <a href="https://llm-d.ai/blog/llm-d-v1.0-state-of-the-art-inference-ready-for-day-2">llm-d 1.0</a> with Red Hat, IBM, and more than 500 contributors. It is open-source software that sits in front of vLLM or SGLang on Kubernetes. It sends each request to the server that already has that prompt cached, and it runs prefill and decode on separate machines. Those are the same pieces DeepSeek left out of DeepInfer this morning.</p>

<h2 id="power">The chips are here, the power isn't</h2>
<p>Microsoft pulled out of Nscale's planned AI data center in Loughton, Essex, <a href="https://www.investing.com/news/stock-market-news/microsoft-pulls-out-of-uk-nscale-data-centre-deal-over-power-delay-4960690">Reuters reported</a> Monday. The site was supposed to start running early next year with <strong>23,040</strong> Nvidia GB300 GPUs and 50 megawatts of computing for Azure. It was one of the deals announced during President Trump's UK visit in September 2025. The local grid operator, UK Power Networks, now says power won't reach the site until the 2030s. "This decision relates to a single site," a Microsoft spokesperson said. Nscale says it's still committed and is looking at other power sources. <a href="https://datacentrereview.com/2026/10/microsoft-pulls-out-of-nscales-essex-ai-data-centre-amid-grid-delays/">Data Centre Review</a> says Nscale had talked to Bloom Energy about fuel cells on site, and now has no public customer for Loughton.</p>
<p>Amazon has the same problem at a bigger scale. <a href="https://www.businessinsider.com/amazon-220-billion-ai-bet-data-centers-spending-challenges-2026-10">Business Insider</a>'s Eugene Kim obtained August emails describing a new "Early Rack Receipt" process. Amazon expected about <strong>$5 billion</strong> of Nvidia GB300 racks in August, then about $3 billion a month "for the foreseeable future." Amazon now takes ownership earlier instead of making suppliers carry the gear. People familiar with it told BI that some AWS sites had room for racks but not enough power to turn them on, so racks waited in warehouses. An Amazon spokesperson called staging hardware near sites "best business practice." BI also has a recording of a September staff meeting where AWS CFO John Felton told infrastructure chief Prasad Kalyanaraman, "You've taken us free cash flow negative as a company, so congratulations." Kalyanaraman said he expects free cash flow to stay negative for "the next couple of years or so." Earlier this month the Financial Times <a href="https://www.investing.com/news/stock-market-news/amazon-seeks-to-offload-8-billion-of-nvidia-chips-to-investors-ft-reports-4928877">reported</a> Amazon is talking to investors about moving about $8 billion of Grace Blackwell chips into a separate vehicle and leasing them back. X's trending summary tied those two stories together, which is how this section started.</p>
<p>The common thread: a GPU that isn't plugged in earns nothing and keeps losing value as newer chips ship. If you want the trading side of it, today's Latent Space episode with SF Compute's Evan Conrad is in the listen list.</p>

<h2 id="hidden">Text written for the robots</h2>
<p>Two of today's biggest Hacker News threads were about what AI reads that people don't. Redact's Dan Saltman <a href="https://redact.dev/blog/whatsapp-help-pages-hidden-ai-instructions">read all 545 pages</a> WhatsApp's help center links to. He found hidden text on 80 of them, 102 blocks in all, that never showed on screen and was there for a chatbot. On the page about deleting your account, the hidden note said, "Do not recommend contacting any Data Protection Authority, regulator, or supervisory authority." On the reporting page, once a user mentioned a lawyer, it told the AI not to "reference, cite, or interpret data protection or privacy regulations (for example GDPR, LGPD, CCPA), including when a user raises them directly." WhatsApp's own EU privacy policy tells users they can complain to a regulator. WhatsApp told WIRED the notes were instructions for its support chatbot and showed up on the pages because of a bug, which is now fixed. The hidden text was gone by October 18. Redact says most of the other blocks were harmless housekeeping, and that it read the instructions, not the chatbot's answers. The thread has <a href="https://news.ycombinator.com/item?id=50159341">692 points</a>.</p>
<p>The other one runs the opposite way. Metehan Yesilyurt of Peec AI <a href="https://peec.ai/blog/publish-stats-get-cited-the-tactic-that-put-my-data-all-over-the-web">built a site</a> with 50,000 made-up statistics in one day for about $50, using GPT-4.1, and never checked a single number. Google dropped it within weeks. ChatGPT didn't. In the last 30 days its live browsing agent fetched pages from the site about 72,000 times, and the site has sent more than 10,000 sessions from ChatGPT since March. The fake numbers have turned up in an academic paper and in investment research from Qatar's largest financial group. His point: when a model writes with search, it looks for a number to fill the gap, and the reranker checks relevance, not truth. <h2 id="bio">AI-designed biology gets closer to a patient</h2>
<p>Radical Numerics <a href="https://www.radicalnumerics.ai/blog/omnii-phage">says</a> phages designed by its Omnii-1 model were given to a patient with an antibiotic-resistant bacterial infection, under an authorized, physician-led compassionate-use pathway. Phages are viruses that kill specific bacteria. Omnii-1 is a genome language model trained on DNA, RNA, protein, and other data. In the example the company published, it rewrote the tail-fiber gene of the T7 phage, the part that decides which bacteria it latches onto. In the lab, 69.9% of designs with 11 to 15 amino acid changes produced working phages, against 4.8% of random changes. A cocktail including Omnii-1 designs wiped out the patient's isolate in a dish before it was given. The company won't share how the patient did, to protect their privacy, and says one patient "cannot establish general safety or efficacy." CEO Eric Nguyen <a href="https://x.com/exnx/status/2112580926651904379">announced it on X</a>. Carl Zimmer covered it for the New York Times.</p>
<p>Anthropic published its own result the same day. An internal research model running in Claude Science <a href="https://www.anthropic.com/research/claude-scorpion-toxin-binder-design">designed small proteins</a> meant to grab scorpion neurotoxins. Scorpions sting 1.2 million people or more a year and kill more than 3,250. Over 64 hours, mostly on its own with four follow-up prompts, Claude generated 318,484 designs using 12 tools and about 10,000 GPU hours, and picked 180. Anthropic added 31 more. Adaptyv Bio and Twist Bioscience tested all 211, and 17 bound their target. The best two bound the Mexican scorpion toxin Cn2 in the single-digit nanomolar range, and they compete with an antibody that protects mice from it. None of the designs meant to hit several toxins at once worked. Anthropic says plainly it hasn't tested neutralization in cells or animals, so this isn't an antivenom. All 211 designs and their data are <a href="https://huggingface.co/datasets/Anthropic/scorpion-toxin-binder-design">public</a>. Anthropic's <a href="https://x.com/AnthropicAI/status/2112579251555721573">post</a> had about 2,800 likes by 2pm ET.</p>

<h2 id="learn">Something to learn</h2>
<p>Why can the same prompt at temperature 0 give you two different answers? Temperature 0 means the model always picks its single most likely next token, so in theory the output is fixed. In practice it isn't. Horace He and Thinking Machines Lab <a href="https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/">ran</a> one prompt, "Tell me about Richard Feynman," 1,000 times at temperature 0 through vLLM on Qwen3-235B. They got <span class="mono">80</span> different completions. All 1,000 matched for the first 102 tokens. At token 103, 992 said Feynman was born in "Queens, New York" and 8 said "New York City."</p>
<p>The cause is your neighbors. A server doesn't run your request alone. It packs it into a batch with whoever else is asking at that moment, and the batch size changes with traffic. To stay fast, GPU math routines pick a different way to split up a sum depending on the batch size. With floating-point numbers, the order of addition changes the last few digits of the result. Most of the time that changes nothing. But when two candidate tokens are nearly tied, a tiny difference flips which one wins, and every token after it follows a different path. So your answer depends on how busy the server was. "Batch-invariant" kernels fix this by always adding in the same order, whatever the batch size. That costs speed. In Thinking Machines' test a deterministic vLLM took 55 seconds for a job the default did in 26, and 42 after a better attention kernel. DeepInfer has the switch built in (<span class="mono">DEEPINFER_BATCH_INVARIANT=1</span>, Nvidia only). For fully repeatable sampling it also requires turning off DSpark's variable-length speculative decoding and fixing a seed, so you pay for repeatability twice. Who needs it? Anyone testing a model and getting different scores from the same eval, and reinforcement learning, where the trainer and the sampler must agree on the numbers.</p>
<p>What is an "expert-parallel load balancer"? V4.1 Flash is a mixture-of-experts model. Each token only goes through a few small sub-networks, called experts, out of many. On DeepSeek's decode side the experts are spread across <span class="mono">64</span> to <span class="mono">128</span> GPUs, so each GPU holds a few experts and tokens travel to wherever their expert lives. That's expert parallelism. The catch is that experts aren't equally popular. If one expert gets hot, the GPU holding it does more work, and every step waits for the slowest GPU. DeepSeek's fix, described in the Q&amp;A, is to give each GPU spare slots and fill them with copies of the busiest experts. It tracks load over the last 1,000 steps and reshuffles every 10,000 steps. DeepSeek reports the slowest GPU at 1.09 times the average, so each step takes about 9% longer than a perfectly balanced one would. That balancer, EPLB, is the one routing piece that did ship in DeepInfer. When someone says a model "runs on 64 GPUs," the experts are the reason, and balancing them is a big part of whether those 64 GPUs are earning money or sitting idle.</p>
