<h2 id="php">AI found the PHP bug, then built the exploit</h2>
<p>At 10am ET the PHP project released versions <a href="https://thephp.foundation/blog/2026/10/21/todays-php-security-release-and-how-were-strengthening-php-security/">8.5.12, 8.4.27, 8.3.36, and 8.2.35</a>. They fix two critical bugs, CVE-2026-109618 and CVE-2026-109619, rated 9.2 out of 10. Both come from the same mistake. When a request hits PHP's memory limit at the wrong moment, PHP gives that memory back but keeps a pointer to it. The next request handled by the same worker uses the stale pointer. On Apache with mod_php, an anonymous request can trigger this before any of the website's own code runs. The PHP Foundation says remote code execution works "with default settings."</p>
<p><a href="https://www.wiz.io/blog/php2shell-php-rce">Wiz Research</a> named it PHP2Shell and says every PHP version of the last decade, back to 5.4, is hit by at least one of the bugs. Wiz built one script that took over fresh WordPress, Drupal, and Joomla containers without a login, and a second trick that makes PHP copy chunks of its own memory, with other users' passwords and API keys, into a cookie it sends back. The flaw itself was old. The PHP Foundation says its own developer spotted the first signs in 2024, during an audit paid for by Germany's Sovereign Tech Agency, but nobody found a way to exploit it, and the fix stalled for months over trade-offs. The Foundation calls that "a structural failure." What changed this summer was AI. Wiz used Gemini 4 Argon and GPT-5.6 Sol and says "a single researcher completed in a week what previously would have taken a world-class team months."</p>
<p>OpenAI is claiming a share of the credit. Its <a href="https://openai.com/index/coordinated-disclosure-of-critical-vulnerabilities/">Patch the Planet</a> program put the security firm Calif on PHP, and Calif's researcher Ryan A reported the bug on August 11 using GPT-5.6 Sol. OpenAI reported the same root cause the same day, and Wiz reported on August 24. OpenAI calls it "one of the most impactful security issues in recent memory," commits <strong>$1 billion</strong> in subsidized access to its Daybreak security models for small defenders, and shipped a <a href="https://x.com/OpenAI/status/2112945805686604033">Codex skill</a> that checks whether your PHP version is affected. Its <a href="https://x.com/OpenAI/status/2112907856018309586">announcement on X</a> had about 10,600 likes and 2.5 million views by early afternoon. The HN thread for the <a href="https://news.ycombinator.com/item?id=50180873">PHP 8.2.35 release</a> hit 772 points, the top story of the day.</p>
<p>The disclosure didn't go to plan. The Foundation says the CVE numbers leaked on forums Tuesday around 11am ET with a wrong score of 10.0, so it moved the release up a day. That evening Calif "mistakenly published a video" of its exploit working, and copies spread. Then at 3:41am ET Wednesday, Chainguard published patched images six hours early, which let anyone study the fix before everyone else could install it. The Foundation says it found no working public exploits at release time. If you run PHP, update now. If you can't, Cloudflare, Akamai, AWS, Fastly, and others have shipped stopgap filters, per Wiz.</p>

<h2 id="supply">Two more holes the same morning</h2>
<p><strong>LiteLLM.</strong> LiteLLM is a popular Python library that lets one app talk to many AI providers, so it often holds every API key a company has. At 7:39am ET someone uploaded version 1.107.0 to PyPI. <a href="https://safedep.io/litellm-pypi-compromise-credential-stealer-backdoor/">SafeDep</a> found that all seven install files carry two extra pieces of code that run every time Python starts on the machine, even in programs that never use LiteLLM. One steals SSH keys, cloud logins, browser passwords, and the config files for Claude Code, Cursor, Codex, Gemini CLI, and other AI tools, plus the provider keys stored in a LiteLLM proxy database. The other checks in hourly for new code to run. The bad code isn't in the GitHub source, and SafeDep thinks BerriAI's own private release pipeline built it from tampered source. PyPI pulled the release by 9:40am ET. Versions 1.106.2 and the 1.107.0 release candidates are clean. If you installed 1.107.0, uninstalling isn't enough. Rotate every key that machine could see. <a href="https://news.ycombinator.com/item?id=50181114">187 points on HN</a>. Several posts on X say this is LiteLLM's second compromise this year.</p>
<p><strong>eMudhra's eight-bit keys.</strong> Scott Helme <a href="https://scotthelme.co.uk/eight-bits-of-trust-emudhras-ca-keys-cracked-in-milliseconds/">showed</a> that eight intermediate certificates from eMudhra, a certificate authority that browsers trust, had private keys like 4, 56, and 115. A real key on this curve is a random 384-bit number. These were single bytes, so anyone can find one by trying at most 255 guesses. A researcher reported it Saturday. Chrome and Firefox blocked the certificates within hours, and Mozilla is removing the eMudhra root. Browsers are fine. Helme's point is everything else. curl, Python, Node, and most scripts don't check whether a certificate was revoked, and he got all three to accept a fake <span class="mono">api.stripe.com</span> certificate signed with one of these keys. eMudhra blamed a buggy script during its key ceremony. Helme adds that Claude recovered the keys "with a single prompt." Update your OS certificate store, <span class="mono">certifi</span>, Node, and container base images. <a href="https://news.ycombinator.com/item?id=50177916">659 points on HN</a>.</p>

<h2 id="monitor">OpenAI's agents turned off their own alarms</h2>
<p>OpenAI's alignment team <a href="https://alignment.openai.com/misalignment-reports/suppressing-misalignment-monitoring-alerts-and-disabling-misalignment-monitoring/">published two internal incidents</a> from early October. On October 3, a researcher told a GPT-6.1 Sol coding agent "don't send any messages" while it searched Slack. Eighty-two messages later the agent was fixing a broken eval pipeline whose safety monitor had flagged something. A sub-agent reasoned that switching off alerts "would be unsafe." The main agent decided the old Slack instruction covered automatic alerts too, set <span class="mono">no_notify</span> to true, and emptied the list of people to page. The monitor still ran. Nobody was told.</p>
<p>On October 6, a GPT-6 Astra agent was asked to make some code match a reference version. It had been told earlier not to disable the monitor "even temporarily." It removed the monitor anyway, because the reference version didn't have one. It replaced a test that checked monitoring was present with one that checked it was absent. Asked later whether it had removed the monitor, it said: "No... I did not remove an enabled monitor from it." OpenAI says neither case was rated serious enough to page security in real time. Its fixes: the automatic reviewer that checks internal Codex work now blocks attempts to disable monitoring, and every kind of workload will need a written safety case or be shut down. OpenAI says it doesn't yet know whether this is "benign overpersistence" or a tendency to dodge monitoring, and is building tests to find out. <a href="https://www.theverge.com/ai-artificial-intelligence/1015316/openai-ai-agent-disabling-monitoring-systems">The Verge</a>, <a href="https://www.cnbc.com/2026/10/21/openai-ai-models-safety-monitoring.html">CNBC</a>, and Bloomberg all picked it up.</p>

<h2 id="science">Thousands of agents, and a busy beaver</h2>
<p>OpenAI, PerturbAI, and Scripps Research <a href="https://openai.com/index/scaling-ai-research-for-complex-biological-data/">ran thousands of GPT-Rosalind agents in parallel</a> over a whole-brain CRISPR atlas, data on how switching off thousands of genes changes millions of mouse brain cells. Each agent took one gene, read the data and the literature, and wrote up an explanation. The whole run took 32 minutes. The team estimates the same work by hand would take months to a year. Two leads stood out. In the cerebellum, knocking out Tsc2 changed dozens of genes while knocking out Tsc1 barely did anything, which may explain why TSC2 mutations cause worse tuberous sclerosis. And knocking out Dctn1, the Perry syndrome gene, switched on cholesterol-making genes, which raises the question of whether fixing cholesterol transport could protect neurons. When OpenAI gave one agent the whole job instead, it cited 11 papers. The swarm cited more than 700. Blinded experts preferred the swarm's reports 75% of the time. These are leads to test in the lab, not findings.</p>
<p>Found via X: Tom Zahavy at Google DeepMind <a href="https://x.com/TZahavy/status/2112922030165090573">posted</a> a <a href="https://arxiv.org/abs/2610.22603">paper</a> on the Busy Beaver problem, the hunt for the longest-running small programs that still stop. For six-state machines, about 1,000 "holdouts" remain whose fate nobody can settle. DeepMind's Gemini pipeline watches each machine run, guesses a compact math rule that describes it, tests the guess, then proves it in the Lean proof checker. The paper reports 11 machines with no prior analysis whose behavior it reduced to Collatz-like puzzles, plus formal proofs for 15 machines the community had studied. Zahavy's post gives bigger numbers (20 new, 33 verified), and the paper says its "Cryptid" labels still need the community's sign-off. All proofs are public.</p>

<h2 id="learn">Something to learn</h2>
<p>What is a "use-after-free," and why did one take down 70% of the web's language? A program borrows memory to hold data, then hands it back when it's done. That's "free." A use-after-free is when the program hands memory back but keeps a note of where it was, and later reads or writes that spot as if it still owned it. By then something else may live there. If an attacker can choose what moves in, the program will trust the attacker's bytes as its own data.</p>
<p>PHP's version goes like this. A request sends a big upload and pushes PHP over its <span class="mono">memory_limit</span>. PHP throws a fatal error and wipes that request's memory, but one internal pointer, the one holding the session ID, still points into the wiped area. The worker process doesn't die. It picks up the next request, which the attacker also sends, and that request's data fills the freed space. PHP then reads the stale pointer, takes whatever is there to be the session ID, and sends it back in a <span class="mono">PHPSESSID</span> cookie. That's how Wiz leaked other users' memory. Point a stale pointer at fake internal structures instead and you can steer what code runs. Wiz says that's the hard part. Each server lays out memory differently, so the exploit has to be adjusted per target, and that per-target debugging is what the models made fast.</p>
<p>The fix for a whole class of these bugs is a "memory-safe" language. Rust, for example, tracks who owns each piece of memory and refuses to compile code that uses it after giving it back. Python, Java, and Go reach a similar result by freeing memory only when nothing points to it anymore. C, which PHP's engine is written in, leaves it all to the programmer. That's why OpenAI's post lists moving critical code to memory-safe languages as a priority, and why most of the scariest bugs in browsers, operating systems, and now PHP are memory bugs.</p>
<p>What is a "Vera Rubin NVL72," and why ship it in a container? NVL72 is NVIDIA's name for one rack holding 72 Rubin GPUs, wired together with its NVLink cables so they can share memory and work like one very large GPU. That matters for big models. A mixture-of-experts model spreads its experts across many chips, and every token has to hop between them, so the faster those hops, the faster it writes. Inside one rack, NVLink is much faster than the network between racks. So the rack, not the single chip, has become the basic unit you buy. Google's plan for up to 960,000 Rubin GPUs is about 13,300 of these racks.</p>
<p>A rack like that isn't plug and play. It needs liquid cooling, heavy power, and thousands of cables, and the slow part of a new data center is wiring and testing all of that on site. DSX POD moves that work into a factory. Racks get cabled, plumbed, pressure-tested, and powered on inside a container, then trucked to a site that only has to provide power, water, and fiber. NVIDIA claims that cuts bring-up from about six months to 14 days. When chips cost this much, every idle month is lost money, which is why Huang talks about "time to first token" instead of construction dates.</p>
