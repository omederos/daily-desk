<h2 id="dont-ask-again">"Don't ask again" kept the password too</h2>
<p>Security company Apiiro <a href="https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again">published</a> on Friday that Claude Code's permission button has been writing secrets into a file people commit. When Claude Code asks to run a shell command and you pick "Yes, and don't ask again," it saves an allow rule to <span class="mono">.claude/settings.local.json</span>, which Anthropic's <a href="https://code.claude.com/docs/en/permissions">permissions docs</a> confirm. Sometimes the rule is a pattern like <span class="mono">npm test *</span>. Sometimes it is the exact command you approved, and if that command had <span class="mono">PGPASSWORD=...</span> or an API key in it, the secret is now in the file in plain text. Apiiro reproduced this with Opus 5.5 and Fable 5.1 and says it is how Claude Code behaves, not a quirk of one model.</p>
<p>Apiiro searched public GitHub and found 104,185 copies of the file in 103,617 repositories. About 1.1% of them, 1,122 files, hold at least one secret, 1,379 distinct ones in total. More than a third open a database directly, including 379 database passwords. There are also 43 SSH logins, 42 GitHub, GitLab, and npm tokens, and 23 AWS keys. Older versions of the file in git history hold 734 more secrets that appear in no current copy, and 211 forks carry the same secrets as the repos they copied. Counting the shared <span class="mono">settings.json</span> and saved agent transcripts, the total is 2,539 secrets across 1,994 repos, <a href="https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html">The Hacker News</a> reports. Apiiro didn't test whether the keys still work, but one company it notified confirmed its key had been live.</p>
<p>Claude Code does try to keep the file out of git. The first time it writes it, it adds the path to your global git excludes, per its <a href="https://code.claude.com/docs/en/settings">settings docs</a>. That protects one person on one computer. A clone on a teammate's laptop, a folder that becomes a repo later, or a file already committed gets no protection, because the rule never goes into the project's own <span class="mono">.gitignore</span>. In 539 of the 1,105 repos Apiiro traced, a commit with Claude listed as co-author changed the file, which suggests the agent often commits it itself. Gitleaks caught 564 of the 1,122 files and TruffleHog 643, and 215 slipped past both, since a password after <span class="mono">sshpass -p</span> looks like an ordinary word. Four related bug reports, the oldest from August 2025, were closed by a bot with no reply from Anthropic, Apiiro says. It was the top AI thread on <a href="https://news.ycombinator.com/item?id=50407882">HN</a> at 516 points.</p>
<p>What to do, from Apiiro's list. Run <span class="mono">find ~ -path '*/.claude/settings.local.json'</span> and read every allow rule. Rotate anything secret that ever sat in one, before you clean up history. Then run <span class="mono">git rm --cached .claude/settings.local.json</span> and add the path to the project's <span class="mono">.gitignore</span>. Going forward, put secrets in environment variables like <span class="mono">$DB_URL</span> so the saved rule holds the name and not the value, and approve patterns such as <span class="mono">Bash(npm run:*)</span> instead of single commands.</p>

<h2 id="managers">Running agents like a team</h2>
<p>Coinbase CEO Brian Armstrong <a href="https://x.com/brian_armstrong/status/2119112609223827547">posted</a> his setup on Saturday, and it drew about 12,000 bookmarks and 1.1 million views. He runs one lead agent per area of focus, all the time, under a "chief of staff" agent. Each lead runs sub-agents that write code, test it, chase reviews, and coordinate with people. Everything he has to decide lands in one prioritized queue, a small local web app, with screenshots and a video demo for each product review. He clears it in batches, mostly by voice. The system keeps a "Brian brain" of his preferences so drafts need fewer corrections. "Every change still goes through the same human review and security checks," he wrote.</p>
<p>Addy Osmani, who works on Claude Code at Anthropic, published an X article early Sunday, <a href="https://x.com/addyosmani/status/2119332146485891501">"Your coding agents made you a manager"</a>, with about 4,600 bookmarks by midday. His first rule is to give the agent a check it can run, a test suite, build, or screenshot, and ask for the proof, because an agent stops when the work looks done. He says to write down any correction you've made twice, in <span class="mono">CLAUDE.md</span> or a skill. He also says to restart with a better prompt after two failed corrections, and to review a diff as if you'll get paged for it. Before an unattended run, he asks five questions. Does it know what done looks like, can it check itself, what are its boundaries, what stops it, and who approves the output? He calls the cost of each extra agent an "orchestration tax." Most days he runs four or five background agents, and "some days that's too many."</p>
<p>Not everyone is adding agents. Goldman Sachs updated internal guidance in October to restrict Claude Code and GitHub's coding tools to its roughly 12,000 engineers, cutting off most traders and bankers, Bloomberg reported last week, per <a href="https://www.thestateofai.com/news/goldman-sachs-claude-code-traders-bankers">State of AI</a>. Traders had used them to watch client flows and model positions. Goldman is also a lead underwriter on Anthropic's IPO. And the highest-scoring new AI thread on <a href="https://news.ycombinator.com/item?id=50410107">HN</a> today, at 589 points, was Caleb's <a href="https://caleb.software/posts/claude-to-pi.html">"Goodbye Claude, hello Pi"</a>, first posted in September and updated Saturday, about leaving Claude Code for the open-source Pi harness. He counts 244 Claude Code releases this year, more than three quarters of which changed the system prompt or tool descriptions. He says the Bash tool's description alone is almost 3,000 tokens.</p>

<h2 id="h200">Cleared to handle H200s, with nobody at the address</h2>
<p>The New York Times <a href="https://www.businesstimes.com.sg/companies-markets/telcos-media-tech/empty-offices-ties-blacklisted-firms-inside-chinese-companies-us-cleared-nvidia-chips">visited</a> the listed office of New Matrix, a 17-month-old Chinese firm the Commerce Department approved this year to assemble Nvidia H200 chips into AI servers. It found an empty shell in a Beijing industrial park with wires hanging from the ceiling. The building directory and property manager had no record of the company. Corporate records tie its owners to Wise Road, a private equity fund on the US entity list since 2024. In September the Times found the same at Maginfra, another approved assembler, which analysts believe is an offshoot of Inspur, also on the entity list. About two dozen Chinese firms appear to have approval, including Baidu, BYD, and Tesla Shanghai, <a href="https://www.theverge.com/ai-artificial-intelligence/1029483/nvidia-ai-chips-china-blacklist-government">The Verge</a> notes. An approval isn't a shipment, and an empty office isn't proof chips reached the military. But both firms were cleared as middlemen who build servers for someone else, which is where you'd expect a front to sit. This was one of the bigger AI stories on X's news feed Saturday.</p>

<h2 id="cpu">A 284B model on a 64 GB PC, no GPU</h2>
<p><a href="https://github.com/synchopate/llama-modchip">llama-modchip</a>, a set of patches to llama.cpp, runs DeepSeek-V4-Flash, a 284-billion-parameter mixture-of-experts model, entirely in the RAM of a 64 GB machine with no graphics card. The standard 1-bit community build from Unsloth is 76.9 GiB, too big for the roughly 62.5 GiB a 64 GB Linux box can use. The project shrinks it to 56.6 GiB, 1.71 bits per weight on average, by squeezing most of the 256 routed experts to about 1.56 bits. Attention, embeddings, and shared experts stay at 4 to 5 bits. On a 16-core AMD Zen 5 laptop chip it reads prompts at about 44 tokens a second and writes at 9 to 10, or up to 14.7 with its speculative drafter. It also keeps Claude Code's 40-tool prompt cached in shared memory so a new turn restarts in about 13 ms. The author reports these numbers, and they haven't been reproduced independently. <a href="https://news.ycombinator.com/item?id=50411961">HN</a> had it at 265 points. The learn section explains the bits.</p>

<h2 id="learn">Something to learn</h2>
<p>Why doesn't deleting a leaked password from a git repo fix the leak? Git doesn't store a file once and edit it. Every commit is a full snapshot of the project, and old snapshots stay forever. When you delete <span class="mono">settings.local.json</span> and commit, you add a new snapshot without it. Every earlier snapshot still has it, and <span class="mono">git log -p -- .claude/settings.local.json</span> will print the password back. You can rewrite history with a tool like <span class="mono">git filter-repo</span> and force-push, but that only changes your copy. Everyone who cloned the repo has the full history on their disk. Every GitHub fork has its own copy, which is why Apiiro found 211 forks carrying the originals' secrets. Bots scan public GitHub for fresh keys, often within minutes of a push. So once a secret has been public, treat it as spent. Revoke it, issue a new one, and clean up history only after that. Two more details explain how the file got in. A <span class="mono">.gitignore</span> file lives inside the repo and travels with every clone. A global excludes file like <span class="mono">~/.config/git/ignore</span> lives on one computer and protects nobody else. And ignore rules only apply to files git isn't tracking yet. If the file was committed once, adding it to <span class="mono">.gitignore</span> does nothing until you run <span class="mono">git rm --cached</span> to stop tracking it.</p>
<p>What does "1.71 bits per weight" mean, and how does it fit a 284B model in 64 GB? A model's weights are numbers. Trained models usually store each one in 16 bits. At 16 bits, DeepSeek-V4-Flash's 284 billion weights would take about 570 GB. Quantization stores each weight with fewer bits, rounding it to one of a small set of values. At 4 bits that is 16 possible values. At about 1.5 bits it is roughly three, close to -1, 0, or +1, times a shared scale for each small block of weights. "Bits per weight" is the average over the whole file, and 284 billion times 1.71 bits comes to about 61 GB, or 56.6 GiB. The average hides a mix. Parts that every token passes through, like attention, embeddings, and the shared expert, stay at 4 to 5 bits, because errors there hit every word. The 256 routed experts, which make up most of the file, get squeezed hardest, because each token only uses 6 of them. An error in one expert touches only the tokens routed to it. The project also keeps a few sensitive layers at the edges of the network at about 2 bits. This is why a mixture-of-experts model shrinks better than a dense one of the same size. Most of its weights sit idle on any given token, so they can be stored roughly. The cost is quality. Below about 2 bits, models start to lose facts and make more mistakes, so run your own tasks before you trust a 1.71-bit build with real work.</p>
