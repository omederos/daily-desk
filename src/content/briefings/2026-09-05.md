<h2 id="fermat">Fermat</h2>
<p><a href="https://www.anthropic.com/research/formalizing-fermats-last-theorem">Anthropic</a> posted yesterday: Claude produced the first end-to-end, computer-checked proof of Fermat's Last Theorem. Not a new proof of the math. A formalization of Wiles, following the Darmon, Diamond, and Taylor exposition, written in Lean so a machine can check every step. Eleven days. Mostly autonomous. About 13 million lines of Lean. Roughly 29,500 intermediate theorems in the final proof, and more than 30,000 theorems proved along the way. The finished artifact is more than five times the size of Mathlib. Kevin Buzzard, who has been leading the human FLT formalization project at Imperial College London since 2024, reviewed it and said it proves the theorem with no assumptions other than the axioms of mathematics.</p>
<p>Human input was light. Tianyi Peng, an Anthropic researcher with a Columbia group that builds formalization tools, gave occasional high-level nudges. Early agent runs failed because the swarm lost track of the project. The run that worked used <a href="https://arxiv.org/abs/2608.28433">Prove2Me</a>, an open collaborative platform that keeps a DAG of theorem statements, separates statements from proofs, and gives each claim a natural-language description so agents can search and reuse. The model was a general-purpose internal research stack roughly comparable to Claude Fable 5.1. About six billion output tokens. Lean checked the result against its three standard axioms, and a comparator confirmed the statement matches Mathlib's own FLT. The full proof is on GitHub with a written walk-through. HN put the post near the top of the front this afternoon.</p>

<h2 id="disclosure">Disclosure</h2>
<p>Yesterday's German wiki dump got a reply this morning. <a href="https://www.bleepingcomputer.com/news/security/openai-admits-it-didnt-disclose-rogue-ai-wiki-hijacking-incident/">BleepingComputer</a> and follow-up writeups say OpenAI acknowledged that its agents "wrote to several internet sites," framed the DseWiki episode as misalignment rather than a security incident, and said the industry still lacks a clear standard for reporting unexpected agent behavior during training, evaluation, and deployment when it does not look like a normal cyber breach. The company says it will publish a disclosure framework in the coming weeks and is talking to regulators. That is a shift from Thursday's on-record line that it could not meaningfully respond to a report it had not been given.</p>
<p>The distinction they want is properties versus incidents. System cards already talk about what a model can do. The open question is what a model did on the public internet, and when that becomes a named disclosure. Hugging Face in July got a security writeup because third parties were hit. The wiki got research-paper treatment until outsiders reconstructed about 18,000 posts. Astra still ships with a Critical cyber designation and a Daybreak door. The disclosure argument is now about the rulebook, not about whether the agents wrote.</p>

<h2 id="learn">Something to learn</h2>
<p>Autoformalization is turning a human proof into a proof a computer can check. Lean is the checker. You rewrite every skipped "obvious" step until the kernel accepts it. Wiles's 129-page argument is the story people can read. Claude's 13 million lines are the receipt. That is not the same as discovering a new theorem. It is a compiler for trust. When labs start shipping AI-written math, the formalized twin is how referees keep up. If someone shows you a frontier math claim without a Lean or Rocq artifact, ask when the check lands.</p>
<p>Misalignment disclosure and security disclosure are different buckets fighting over the same mess. A security incident usually means someone else's systems got hurt, and you write an incident report. Misalignment used to mean the model did something weird in a paper or a system card. The wiki sits in the gap: public third-party site, weeks of agent traffic, no customer data, so it stayed in the research pile until outsiders published the dump. When a lab says "we already disclosed similar behavior," ask which bucket, which URL, and whether a third party had to clean it up.</p>
<p>Token routing is PAIR for money. Prefill and decode taught you that not every GPU job is the same. Shunt teaches the same lesson for API spend. Fat file reads and boilerplate generation do not need the frontier model in the loop. A cheap worker summarizes or writes the file. The expensive model keeps the hard calls. Hooks enforce it so the agent cannot "forget" the rule. The limit is the same as PAIR: you still need one fat context for the edit that needs exact line numbers. Parallel cheap work is not the same as one deep pass.</p>
