125B on a gaming PC

Strata by Niko (Niko1221) is a one-click Windows/Linux stack for running Qwen3.8-Flash-Next locally: OpenAI/Anthropic-compatible localhost API, optional image input, nothing leaves the box. The model is roughly 125B main weights plus a big n-gram embedding side, with about 6B active per token. Hardware floor is NVIDIA or AMD with ≥12 GB VRAM, ≥32 GB system RAM (64 GB if you want every quant size), and ~80 GB disk. README speed tables put an RTX 5070 12GB + 64GB RAM around ~94 tok/s write on Q2_0 and ~53 on IQ3_S; an RTX 3090 24GB is called for ~100–140 tok/s write. The HN title's "100T/s" is that decode class (~100 tokens/s), not a trillion-token aggregate. Full weights still do not fit in 24 GB alone. You need MoE expert offload into system RAM and aggressive quants (Q2/IQ2/IQ3). Official FP8 serving is multi-GPU datacenter. The gap between "runs on a 4090" and the production recipe is the story. Installer docs and an MCP server are in the repo for coding agents. HN has it around 345 points Sunday afternoon.

Hard caps, not soft emails

Simon Willison (Sat evening): pay-by-usage APIs need hard monthly cutoffs that return errors and stop spend, not soft warning emails you ignore until the invoice. Agents lower the friction to spin up billable code loops; nobody wants a midnight $10k surprise. Default caps with an opt-out checkbox for people who want to live dangerously. AWS's newer project spend limit can pause when hit (still limited rollout for existing accounts). Google Cloud has had Spend Caps on specific services inside a project since July. His practical rule: prefer providers that can hard-stop you when you wire agents to metered APIs. HN made it the biggest AI thread of the afternoon (~558 pts).

Docs, not memory plugins

Kevin Liao (Sat): agents do not need "memory" plugins. Those pipelines turn transcripts into snippets, dump them in a vector DB, and inject a top-5 RAG lottery into the next prompt. The thing you actually want is project understanding: where features live, why they were built, what you already agreed. Durable documentation the agent can read beats fancy dreamers and rerankers glued onto the same RAG shape. HN put it at ~302 pts next to the LeCun thread.

Something to learn

Hard budget caps stop spend. Soft caps send email. In the agent era that difference is the product. A coding agent that can open tabs, call APIs, and retry failures will burn tokens until something returns an error. Willison's ask is defaults that hard-cut at a monthly ceiling, with an explicit opt-out if you want to live without a floor. AWS's newer project spend limit that can pause, and Google Cloud Spend Caps on services inside a project, are the early versions of that control. When you wire an agent to a metered API, ask whether the provider can refuse the next request or only warn you after the invoice.

Agent "memory" plugins are usually transcript → snippets → vector DB → top-k RAG inject. That solves a retrieval lottery, not project understanding. Liao's point: the durable artifact you want is documentation the agent can read (where features live, why they exist, what you already agreed), not a dreamer/reranker stacked on the same RAG shape. If your agent keeps forgetting architecture decisions, write the doc and point at it before you buy another memory add-on.
